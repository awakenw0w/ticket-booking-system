# Руководство пользователя

Документ описывает работу пользователя с информационной системой бронирования и продажи билетов.

## Назначение системы

Система помогает менеджеру мероприятия:

- вести список мероприятий;
- настраивать категории билетов;
- видеть доступный остаток билетов;
- создавать бронирования клиентов;
- отменять и оплачивать бронирования;
- просматривать отчеты по бронированиям, выручке и заполненности.

## Запуск интерфейса

Перед началом работы backend и frontend должны быть запущены администратором.

Адрес frontend:

```text
http://127.0.0.1:5173/
```

После открытия страницы в верхней части интерфейса отображается статус API. Если backend доступен, статус меняется на `API доступен`.

## Основные области экрана

Интерфейс состоит из нескольких рабочих блоков:

- `Мероприятия` - список мероприятий и форма создания нового мероприятия;
- `Детали` - информация о выбранном мероприятии;
- `Категории` - таблица билетов и форма добавления категории;
- `Заявка клиента` - форма создания бронирования;
- `Бронирования` - журнал заявок;
- `Отчеты` - сводная аналитика.

## Создание мероприятия

1. В блоке `Новое мероприятие` заполнить поля:
   - название;
   - место;
   - дата и время;
   - статус;
   - описание.
2. Нажать кнопку `Создать`.
3. Убедиться, что мероприятие появилось в списке слева.

Рекомендуемый статус для мероприятия, доступного клиентам: `Опубликовано`.

## Выбор мероприятия

1. В списке `Мероприятия` нажать на нужную карточку.
2. В блоке `Детали` проверить название, место, дату начала и остаток билетов.
3. В блоке `Категории` проверить доступные категории билетов.

## Добавление категории билетов

1. Выбрать мероприятие.
2. В блоке `Категории` заполнить:
   - название категории;
   - цену;
   - количество билетов.
3. Нажать `Добавить`.
4. Проверить, что категория появилась в таблице.

Примеры категорий: `Стандарт`, `Фан-зона`, `VIP`, `Партер`.

## Создание бронирования

1. Выбрать мероприятие.
2. В блоке `Заявка клиента` выбрать категорию билета.
3. Указать количество билетов.
4. Заполнить данные клиента:
   - имя;
   - почта;
   - телефон.
5. Нажать `Забронировать`.
6. Проверить, что новая запись появилась в журнале бронирований.

Если запрошено больше билетов, чем доступно, система выводит ошибку и не создает бронирование.

## Отмена бронирования

1. Найти нужное бронирование в журнале.
2. Нажать кнопку `Отменить`.
3. Убедиться, что статус изменился на `Отменено`.

Отменить можно только активное бронирование со статусом `Бронь`.

## Отметка оплаты

1. Найти активное бронирование в журнале.
2. Нажать кнопку `Оплатить`.
3. Убедиться, что статус изменился на `Оплачено`.

Оплаченное бронирование нельзя удалить через API, чтобы не потерять данные для отчетов.

## Просмотр всех бронирований

По умолчанию журнал показывает бронирования выбранного мероприятия.

Чтобы посмотреть все бронирования:

1. Перейти в блок `Бронирования`.
2. Нажать `Показать все`.

## Работа с отчетами

В блоке `Отчеты` доступны фильтры:

- период с;
- период до;
- статус;
- все мероприятия или выбранное мероприятие.

После изменения фильтров нажать `Обновить отчеты`.

Система отображает:

- общее количество бронирований;
- количество билетов в бронированиях;
- сумму бронирований;
- группировку бронирований по статусам;
- выручку по мероприятиям;
- заполненность мероприятий.

## Частые ошибки

| Ситуация | Причина | Решение |
| --- | --- | --- |
| Статус API показывает ошибку | Backend не запущен | Запустить `php artisan serve` |
| Мероприятия не отображаются | База не заполнена | Выполнить `php artisan migrate:fresh --seed` |
| Нельзя создать бронирование | Не хватает билетов | Уменьшить количество или выбрать другую категорию |
| Кнопки оплаты и отмены неактивны | Бронирование уже оплачено или отменено | Выбрать активную бронь |

## Завершение работы

После демонстрации можно закрыть вкладку браузера. Backend и frontend останавливаются администратором в терминалах, где они были запущены.
