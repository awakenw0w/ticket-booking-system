# Модель данных

Документ описывает базовую структуру БД для MVP системы бронирования и продажи билетов.

## Сущности

### `roles`

Роли используются для разделения пользователей по ответственности.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | integer | Первичный ключ |
| `slug` | string | Системный код роли |
| `name` | string | Название роли для интерфейса и документации |
| `created_at`, `updated_at` | timestamp | Служебные даты Laravel |

Тестовые роли: администратор, менеджер, клиент.

### `users`

Пользователи системы. На первом этапе используется стандартная таблица Laravel, дополненная ролью.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | integer | Первичный ключ |
| `role_id` | foreign id | Ссылка на роль |
| `name` | string | Имя пользователя |
| `email` | string | Почта для входа и связи |
| `password` | string | Хеш пароля |

### `events`

Мероприятия, на которые продаются и бронируются билеты.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | integer | Первичный ключ |
| `title` | string | Название мероприятия |
| `description` | text, nullable | Описание |
| `location` | string | Место проведения |
| `starts_at` | datetime | Дата и время начала |
| `status` | string | `draft`, `published`, `finished`, `cancelled` |

### `ticket_categories`

Категории билетов внутри мероприятия. Одно мероприятие может иметь одну или несколько категорий.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | integer | Первичный ключ |
| `event_id` | foreign id | Ссылка на мероприятие |
| `name` | string | Название категории |
| `price` | decimal | Цена билета |
| `quantity` | unsigned integer | Общее количество билетов категории |

Для пары `event_id` + `name` задана уникальность, чтобы в одном мероприятии не было двух одинаковых категорий.

### `bookings`

Бронирования клиентов.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | integer | Первичный ключ |
| `user_id` | foreign id, nullable | Связанный пользователь, если клиент зарегистрирован |
| `ticket_category_id` | foreign id | Выбранная категория билета |
| `customer_name` | string | Имя клиента |
| `customer_email` | string | Почта клиента |
| `customer_phone` | string | Телефон клиента |
| `quantity` | unsigned integer | Количество билетов |
| `status` | string | `reserved`, `cancelled`, `paid` |
| `total_price` | decimal | Итоговая стоимость |
| `reserved_at` | datetime | Дата бронирования |
| `cancelled_at` | datetime, nullable | Дата отмены |
| `paid_at` | datetime, nullable | Дата оплаты |

## Связи

- `Role` 1:N `User`
- `User` 1:N `Booking`
- `Event` 1:N `TicketCategory`
- `TicketCategory` 1:N `Booking`
- `Event` получает бронирования через категории билетов

## Расчетные показатели

- Доступный остаток билетов = `quantity` категории минус количество билетов в бронированиях со статусами `reserved` и `paid`.
- Выручка = сумма `total_price` бронирований со статусом `paid`.
- Заполненность мероприятия = количество забронированных и оплаченных билетов / общее количество билетов по всем категориям.

## Тестовые данные

Сидер создает:

- 3 роли;
- 3 пользователя;
- 2 мероприятия;
- 4 категории билетов;
- 4 бронирования в статусах `reserved`, `paid` и `cancelled`.
