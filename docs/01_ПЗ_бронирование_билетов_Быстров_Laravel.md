# Пояснительная записка

Тема: разработка информационной системы бронирования и продажи билетов на мероприятия с различными видами билетов.

Автор: Быстров Егор, группа 3-1ИС.

Стек: Laravel, PHP, SQLite, HTML, CSS, JavaScript, GitHub.

## Введение

Заказчику требуется система, которая помогает вести мероприятия, категории билетов и бронирования в одном месте. Без автоматизации менеджер вынужден вручную проверять остатки билетов, вести списки клиентов и отдельно считать выручку. Это повышает риск ошибок: можно продать больше билетов, чем доступно, потерять отмену бронирования или неверно посчитать отчет.

Цель работы: реализовать MVP информационной системы для бронирования и продажи билетов на мероприятия.

Задачи:

- проанализировать предметную область;
- выделить роли пользователей и функциональные требования;
- спроектировать структуру данных;
- реализовать основу backend на Laravel;
- подготовить тестовые данные;
- описать будущий API;
- добавить автотесты для проверки структуры БД;
- вести код в GitHub через ветки и коммиты.

## Анализ предметной области

В системе участвуют администратор, менеджер и клиент. Администратор отвечает за общую настройку и пользователей. Менеджер создает мероприятия, задает категории билетов, контролирует бронирования и отчеты. Клиент выбирает мероприятие, бронирует билеты и при необходимости отменяет бронирование.

MVP включает:

- управление мероприятиями;
- учет одной или нескольких категорий билетов;
- создание бронирования;
- отмену бронирования;
- фиксацию оплаты;
- отчеты по бронированиям, выручке и заполненности.

Функциональные требования вынесены в `docs/requirements.md`.

## Архитектура

Проект строится как трехзвенная информационная система:

- клиентская часть отображает интерфейс и отправляет запросы;
- API принимает запросы, валидирует данные и выполняет бизнес-логику;
- база данных хранит пользователей, роли, мероприятия, категории билетов и бронирования.

На первом этапе реализована серверная основа: миграции, модели, связи и сидер. Полноценные API-контроллеры и клиентские экраны будут реализованы на следующих этапах.

## Модель данных

Основные сущности:

- `roles` - роли пользователей;
- `users` - пользователи системы;
- `events` - мероприятия;
- `ticket_categories` - категории билетов внутри мероприятия;
- `bookings` - бронирования клиентов.

Связи:

- роль имеет много пользователей;
- пользователь имеет много бронирований;
- мероприятие имеет много категорий билетов;
- категория билетов имеет много бронирований.

Подробная таблица данных описана в `docs/data-model.md`.

## Проект API

API проектируется вокруг основных сущностей MVP:

- `/api/events` - мероприятия;
- `/api/events/{event}/ticket-categories` - категории билетов мероприятия;
- `/api/bookings` - бронирования;
- `/api/reports/*` - отчеты.

Документация API находится в `docs/api.md`.

## Тестирование


## Глоссарий

- API - интерфейс взаимодействия клиентской и серверной части.
- CRUD - создание, чтение, изменение и удаление данных.
- MVP - минимально жизнеспособный продукт.
- Бронирование - временное закрепление билетов за клиентом.
- Категория билета - тип билета внутри мероприятия, например стандарт или VIP.
- Миграция - файл изменения структуры базы данных.
- Сидер - файл заполнения базы тестовыми данными.
